## 2024-05-24 - Expensive string transformations in React renders
**Learning:** LispCentral runs its HTML5 web palette interface inside AutoCAD's embedded browser control, which is significantly slower than modern desktop browsers at executing JavaScript. Performing O(N*M) string re-allocations (like `.toLowerCase()` inside a `.some()` loop nested in a `.filter()`) and recalculating derived states on every render without `useMemo` causes severe UI unresponsiveness and blocking on this specific environment, even if it might run fine on a standard Chrome desktop browser.
**Action:** Always extract expensive string transformations (such as `.toLowerCase()`) outside of `.filter()` or `.some()` closures to prevent O(N*M) performance degradation. Additionally, wrap derived lists (like filtered/grouped arrays) in a `useMemo` hook to ensure calculations only run when their dependency arrays (`commands`, `activeFilters`) change, drastically minimizing string allocations during routine re-renders (like toggling pins).
